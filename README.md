# MoviePilot v3 原盘无损提取

使用 FFmpeg 将**可正常读取的蓝光/UHD Blu-ray、DVD 原盘目录和 ISO**封装为 MKV。视频、全部音轨和字幕使用 `-c copy`，不重新编码；复制章节和元数据。仅复制导航器暴露的所选标题轨道，蓝光菜单、BD-J、交互功能和附件不属于输出内容。

## 安装

1. 在 MoviePilot v3 的第三方插件仓库设置添加 `https://github.com/iumuu/MoviePilot-Plugins-DiscRemux`。
2. 刷新插件市场，安装「原盘无损提取」（插件 ID：`DiscRemux`）。
3. 配置容器内输入、输出绝对路径，以及 FFmpeg / FFprobe 程序路径。
4. 勾选「保存后立即运行一次」进行首次处理；需要自动扫描时开启周期扫描。

采用 `package.v3.json` + `plugins.v3/discremux/`，原生 Vuetify 配置界面；使用当前 MoviePilot v3 SDK（包括 `app.sdk.scheduler.add_plugin_once_job`）。旧版 v3 如果缺少该接口，请更新宿主。没有 Python 第三方运行依赖。

## FFmpeg 依赖和 ISO 支持

FFmpeg 与 FFprobe 必须来自具备相同导航功能的构建：

| 来源 | 必需能力 | 默认标题 |
| --- | --- | --- |
| 蓝光/UHD 目录（包含 BDMV）或 ISO | `bluray` 协议，编译启用 libbluray；ISO 读取还取决于 libbluray 的 UDF 支持 | libbluray 主标题 |
| DVD 目录（包含 VIDEO_TS）或 ISO | `dvdvideo` demuxer，启用 libdvdnav 和 libdvdread | 标题 1 |

检查命令：

```sh
ffmpeg -protocols
ffprobe -protocols
ffmpeg -demuxers
ffprobe -demuxers
```

只装了普通 FFmpeg 不代表具备上述能力。插件启动处理前检查能力，无法读取的 ISO 会显示 FFmpeg 原始错误。**ISO 直接通过导航库读取，无需挂载，也无需容器 privileged 权限。插件不提供解密功能**；加密、损坏或导航混淆原盘可能无法读取。UHD 的 HDR/杜比视界等是否完整保留取决于 FFmpeg、输入轨道及封装支持，当前未完成这些格式的样本验证。

蓝光按播放列表读取全部分段，不拼接最大 M2TS；可填写播放列表号，例如 `800` 对应 `00800.mpls`。DVD 可填写标题号，例如 `2`。多版本或剧集原盘需要分次选择标题，不会自动识别所有集数。目录类型自动识别；ISO 类型使用配置项，混合蓝光/DVD ISO 请分批处理。

## 路径示例

```yaml
# 合并到现有 MoviePilot compose 的 volumes 中
volumes:
  - /media/discs:/discs:ro
  - /media/remux:/remux
```

输入 `/discs`，输出 `/remux`。输入也可以是单个 ISO 或包含 BDMV/VIDEO_TS 的原盘根目录。不要直接填写 BDMV/STREAM。输出可以位于扫描目录内，例如输入 `/media/downloads`、输出 `/media/downloads/REMUX`；扫描时自动排除整个输出目录。输出不能与输入相同，也不能是输入的父目录。请仅扫描已下载完成且不再写入的原盘，插件不连接下载器判断下载状态。

输出保留相对目录，ISO 去掉扩展名后加 `.mkv`，原盘目录名直接加 `.mkv`：`Film.iso` → `Film.mkv`；指定标题时为 `Film.800.mkv`。现有输出直接跳过，也兼容检测旧的 `.iso.mkv` / `.disc.mkv` 命名，不自动重命名已有文件。同目录下同名 ISO 和目录视为同一输出，后处理者跳过；如需两份结果，请分别指定输出目录。若更换了同名源文件，请使用「重新提取一次」。

## 任务与数据保护

- 串行处理，重复触发不会并发执行；停止/重载时取消当前 FFmpeg 子进程。
- 先写同目录临时 MKV，成功后检查视频/音频/字幕的编码与数量、时长差异、章节数量，再原子创建最终文件。检查不等于逐帧解码验证。
- 输出文件系统必须支持硬链接（常见 ext4、Btrfs、NTFS 支持；部分网盘/FUSE/SMB 挂载不支持）。不支持时任务失败，不会退化为覆盖写入。
- FFmpeg 不支持的字幕或音频会使任务失败，不会悄悄转码或丢弃轨道。
- 正常失败/取消清理本次临时文件和锁；宿主崩溃或断电可能留下 `.partial.mkv` / `.mkv.lock`。确认没有活跃任务后手工删除对应残留再试。
- 源文件只读，不删除、不改名；预留足够输出空间。最近 100 条任务结果显示在详情页。

## 1.1.0 自动准备系统工具

默认开启「优先使用系统版 FFmpeg」，使用 /usr/bin/ffmpeg 和 /usr/bin/ffprobe，避免 PATH 选到 /usr/local/bin 的静态构建。自定义路径仅在关闭此选项后生效。

在插件配置开启「缺失时自动安装系统版 FFmpeg」并保存，扫描前会检测工具；缺失时使用系统已有 apt 软件源执行 update 和 install ffmpeg。仅支持 Debian/Ubuntu 类环境，需要容器 root、可写系统目录和网络。安装开关默认关闭，开启后持续生效；容器重建后，只要 MoviePilot 配置卷保留，下次扫描会自动补装。已有工具不会重复安装或自动升级。依赖准备状态显示在详情页和日志中，失败时终止扫描。

为避免普通停止操作打断软件包配置，停止请求在当前 apt 步骤完成后生效，单步最多 15 分钟；外部强制关闭容器或安装超时仍可能需要人工修复包管理器状态。不自动覆盖 /usr/local/bin 文件，不自动安装 Java，不修改镜像本身。自动安装只能准备依赖，不能保证解决所有原盘或 FFmpeg 缺陷。

自动安装分支已通过模拟测试，未在本项目环境实际运行容器内 apt；用户已验证 Debian 7.1.5 工具可读取此前导致静态 8.1.1 崩溃的目录原盘。

## 1.2.0 实时进度

使用 FFmpeg -progress 采集真实进度，每 2 秒更新内存状态，日志每 10 秒输出一次，阶段切换立即记录。显示已处理时长、百分比、输出大小、处理速度及预计剩余时间。源总时长未知时不显示百分比；速度未知时不估算剩余时间。FFmpeg 时间戳可能带来估算偏差，只有输出校验通过后才显示完成 100%。

在 MoviePilot 首页仪表板添加「原盘提取进度」卡片，可每 3 秒自动刷新；插件详情页显示最近状态，是否自动刷新由宿主决定。探测和校验阶段显示已等待时间，不伪造该阶段的完成比例。

## 1.3.0 持久完成记录

校验成功并生成最终输出后，在 MoviePilot 插件数据库保存独立成功记录，不受最近 100 条日志上限影响。按源绝对路径、原盘类型、标题编号去重，不依赖输出目录或输出文件：成品上传网盘并删除后，保留做种的源文件仍会跳过。失败不会写入成功记录，后续扫描可重试。已有输出但没有成功历史时只跳过文件，不把未验证文件认定为成功。

升级会按扫描到的源路径迁移仍保留的旧成功日志。旧日志没有标题信息时只匹配默认标题；已经从最近 100 条日志中消失的成功记录不能自动恢复。保留 MoviePilot 配置和数据库；清除插件数据会清除去重记录。

需要重做时，把输入改成单个 ISO 或原盘根目录，勾选「重新提取一次」保存。此操作忽略成功记录，若旧输出仍在则生成 .redo-随机编号.mkv，不覆盖旧文件。开关保存后自动关闭。重做失败保留先前成功记录，需要再次手动重做。

记录不对源文件做内容哈希：同一路径替换成另一份原盘需要主动重做；移动/改名后的源路径视为新任务。更换输出目录不会绕过记录。

## 1.3.1 蓝光语言标签

从 FFprobe 日志确认自动选中的播放列表，并固定该列表用于封装。目录直接读取 MPLS；ISO 在独立 Python 子进程通过系统共享库 libbluray 读取 MPLS，避免原生库故障影响宿主。按主路径 PID 补齐主音频和 PGS/Text 字幕语言，优先保留 FFprobe 已有标签，并验证输出语言标签。

无法确定播放列表、缺少共享库或解析失败时在日志中警告，未知语言仍保留 und。子路径轨道和跨片段语言冲突不猜测。当前测试使用合成 MPLS，尚未在真实 ISO 上完成语言回填端到端验证。

已有 MKV 不自动修改；已完成任务默认跳过。要重新提取，请将输入指向单个 ISO/原盘目录，勾选「重新提取一次」。旧输出保留，新文件带 redo 后缀。

## 1.3.2 蓝光章节

从实际选中 MPLS 的 entry mark 读取章节，减去各播放片段的 IN 时间并累加前序片段长度，按 1/45000 时间基生成 FFmetadata CHAPTER 输入，再用 map_chapters 写入真正的 MKV 章节。输出后校验章节数量和起止时间。MPLS 通常只记录位置，名称生成 Chapter 01 等，不承诺恢复菜单中的章节名称。

MKVToolNix 显示的编码器/时长等标签可以与章节同时存在，标签本身不表示章节被转换。读取失败时会警告并回退到 FFprobe 已有章节；若二者都没有章节，则仍无法恢复。已有 MKV 不自动修复，需要使用单部重新提取。分段时间计算使用合成 MPLS 测试，真实原盘端到端验证待完成。

## 1.4.0 数据页记录操作（取代此前配置重提开关）

配置页不再提供重新提取开关，遗留 redo_once 配置不会触发重提。在「查看数据」顶部可清除全部记录；每条原盘记录右侧提供「清除单条记录」「重新提取」。同一路径与标题的重复历史合并展示，持久完成记录即使超出 100 条日志也会显示。

清除会同时清除对应成功标记和历史，保留原盘与输出文件；输出已被删除时，下次周期扫描会重新提取。重新提取只使用选中记录的原盘路径、标题和已记录的类型，使用当前输出目录，已有输出生成 redo 新文件。旧历史没有类型时使用当前 ISO 类型设置。运行或等待任务期间禁用操作，避免并发清除或重复提交。界面通过宿主原生 POST 事件调用登录鉴权接口，不接受任意路径参数。
